# MicroPool — Agreed Contracts (Rack 1)

This is the whiteboard agreement, written down. Change it via team agreement, not
unilaterally — all three services depend on these shapes matching.

## 1. Versions & build

- Java 21
- Spring Boot 3.3.x
- Maven (each service has its own independent `pom.xml`, no shared parent POM)
- All services listen on **port 8080 inside their container**

## 2. Project structure

```
MicroPool/
  match-service/
  shot-service/
  league-service/
  docker-compose.yml
  CONTRACTS.md
  README.md
```

Each service is independently buildable and deployable. No shared code/DTO modules —
each service defines its own request/response classes. This is deliberate: it is a
microservice boundary, not an oversight.

## 3. Compose service names (DNS hostnames)

| Service | Compose name | Internal port | Host port (debug only) |
|---|---|---|---|
| Match Service | `match-service` | 8080 | 8081 |
| Shot Service | `shot-service` | 8080 | 8082 |
| League Service | `league-service` | 8080 | 8083 |
| Postgres | `postgres` | 5432 | 5433 |

Match Service calls Shot Service at `http://shot-service:8080`.
Match Service calls League Service at `http://league-service:8080` (on match completion).
League Service connects to the DB at `postgres:5432`.

**Never use `localhost` for container-to-container calls.**

## 4. Identifiers

`matchId` is a `String` UUID, generated by Match Service at creation time. Passed
as-is to League Service in the result payload. Avoids coordinating auto-increment
sequences across two services.

## 5. API contracts

### Match Service

**POST `/matches`** — create a match

Request:
```json
{ "player1": "Alice", "player2": "Bob" }
```

Response `201 Created`:
```json
{
  "matchId": "b3f1c2a0-...",
  "player1": "Alice",
  "player2": "Bob",
  "status": "ACTIVE",
  "currentTurn": "Alice",
  "ballsRemaining": {
    "Alice": ["SOLID_1", "SOLID_2", "SOLID_3", "SOLID_4", "SOLID_5", "SOLID_6", "SOLID_7"],
    "Bob": ["STRIPE_9", "STRIPE_10", "STRIPE_11", "STRIPE_12", "STRIPE_13", "STRIPE_14", "STRIPE_15"]
  },
  "eightBallPotted": false,
  "winner": null
}
```

Ball groups are pre-assigned at creation (solids = player1, stripes = player2).
No "open table" phase — deliberately simplified per the spec.

**GET `/matches/{id}`** — read match state. Same shape as the create response, reflecting
current state.

**POST `/matches/{id}/shots`** — take a shot

Request:
```json
{ "player": "Alice", "angle": 37, "power": 72, "spin": 0 }
```
`spin` is optional, defaults to `0`. `player` must match `currentTurn` or the
request is rejected (409).

Response `200 OK`:
```json
{
  "shotResult": "POT_TWO",
  "ballsPotted": 2,
  "foul": false,
  "turnChanged": false,
  "match": { "...": "full match state, same shape as GET /matches/{id}" }
}
```

Error shapes:
```json
// 409 Conflict — wrong turn or match not active
{ "error": "NOT_YOUR_TURN", "message": "It is Bob's turn." }

// 400 Bad Request — invalid input
{ "error": "INVALID_INPUT", "message": "angle must be between 0 and 359" }

// 502 Bad Gateway — Shot Service unreachable/timed out (Rack 3)
{ "error": "SHOT_SERVICE_UNAVAILABLE", "message": "Could not resolve shot outcome, try again" }
```

### Shot Service

**POST `/shots`** — calculate a deterministic shot outcome

Request:
```json
{ "angle": 37, "power": 72, "spin": 0 }
```

Response `200 OK`:
```json
{ "result": "POT_TWO", "resultCode": 9 }
```

Deterministic rule (starting point, per spec):
```
resultCode = (angle + power) % 10
0        -> FOUL      (cue ball potted)
1 to 4   -> MISS
5 to 8   -> POT_ONE
9        -> POT_TWO
```
Shot Service is stateless: no knowledge of matches, players or turns.

### League Service

**POST `/results`** — record a completed match

Request:
```json
{
  "matchId": "b3f1c2a0-...",
  "winner": "Alice",
  "loser": "Bob",
  "completedAt": "2026-08-11T15:56:00Z"
}
```

Response `201 Created`: echoes the stored result.

**GET `/leaderboard`** — current standings

Response `200 OK`:
```json
[
  { "player": "Alice", "wins": 3, "losses": 1 },
  { "player": "Bob", "wins": 1, "losses": 3 }
]
```
Sorted by `wins` descending, server-side.

## 6. Health checks

All services expose Spring Boot Actuator `/actuator/health`. Compose health checks
and startup dependency ordering (`depends_on: condition: service_healthy`) key off
this endpoint.
